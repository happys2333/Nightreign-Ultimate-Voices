## 复测方法

1. 使用原配置启动，在训练场记录同一角色、同一位置和大招动作的表现。
2. 改用 `dist/UltimateVoices/Launch.cmd`，轮流切换十角色施放；检查普通攻击/职业技能不误播，准备取消不误播，释放一次不重复。
3. 两人同版本无缝联机，只有 A 装语音包。分别让 A、B 释放，确认 A 听到本地播报、B 维持原音；随后交换安装端复测。
4. 两端都安装不同语音，各自核对听到的是自己的语音包。测试近处、远处、加载/卸载距离边界。
5. 同设置、同场景交替原配置与新配置测试帧时间。报告实际数据，不以生成声库大小替代 FPS 测试。

本地开发的独立解析证据在 `local/bank_verification/validation.json` 和 `wwiser_hero01.xml`；ME3 初版资产覆盖日志在 `local/me3-load.stderr.log`。这些缓存不进入版本控制。

### 参考工具离线对照

- 使用 [Yonder](https://github.com/ndahn/yonder) 自带的 MIT bnk2json 完整解包、重打包原始无赖声库及 Hash 诊断声库，两者各自重打包前后均逐字节一致。当前未发现 BKHD / DIDX / DATA / HIRC 序列化差异。
- 对照 Yonder 的 Sound / Play Action 构造器，诊断中保留的原生叶节点除媒体编号和大小外与模板字段一致，没有缺失的 owner / dependency 字段。原生层级未消除静音，不能把独立新增 Sound 的 parent 设置认作已确认根因。
- 原生 3,883 个 Vorbis WEM 的 setup 内容与头部 FNV-1 摘要全部匹配；测试用开源 wav2wem 使用固定值，与本次转换 setup 不匹配。修正这一真实格式缺陷仍未解决实机静音，不能夸大为已修复播放。
- 独立 Wwise 引擎离线回归已建立原生正基线；此前高/30 位媒体编号、PCM 头差分、Vorbis 摘要差分及隔离新增图均可播放。PCM 与输入波形相关系数约 `0.998`，Vorbis 约 `0.994`。没有据此继续猜改 PCM 头或总线路由。
