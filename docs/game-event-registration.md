# 提前播报无声：游戏声音索引修正

用户反馈：铁眼、守护者修改时机后听不到 OW，原大招声仍在。最新 ME3 日志确认本模组的动画包与 `hero02/hero03.bnk` 都已加载，排除了启动错包。

上一版创建了三个新 Wwise Event，并在 TAE 写入其 SoundID，但遗漏了游戏侧的两份声音目录：

- `sound/soundbanksinfo.mobnkinfo`（SBI）：声库与 Event 的关联。
- `sound/eventinfo.eib`（WWEI）：声音键与事件标记。

三个原事件均在原目录中，新事件均不在。此前的独立 SDK 测试直接指定新 Event，跳过了游戏目录这一层，所以能证明音频和声库可播，却不能证明游戏已为它们登记/准备播放。

## 本次修改

从本机实际生效资源读取上述目录，固定原文件 SHA-256，只给守护者、铁眼、学者的新增 Play Event 补登记。每项沿用相应原事件的标记。

| 角色 | 新 Play Event | 角色声库 | 登记后的声库 Event 数 |
| --- | --- | --- | ---: |
| 守护者 | `Play_c900207000` | `hero02` | 45 |
| 铁眼 | `Play_c900307000` | `hero03` | 39 |
| 学者 | `Play_c900907000` | `hero09` | 43 |

SBI 两个分区的全部原记录保留，包括 133 个合法空声库记录。只追加三个角色的扩展 Event 数组并更新其计数/指针。EIB Play 表增加三个键，其余 16,648 个原 Play 键及 16,605 个 Stop 键保持原值；未知高位键按原始 uint64 保留。没有为不存在的 Stop Event 添加登记。

SBI 从 277,904 变为 278,920 字节，EIB 从 299,384 变为 449,272 字节。追加数据按八字节对齐。恢复被修改的原计数/指针/文件长度并截去追加区后，原文件逐字节一致；独立审查生成的结果与本构建器一致。

两份目录只写到生成包的 `mod/sound/`。游戏归档、原模组与原启动配置不改动；发现已有目录覆盖或游戏更新导致摘要变化，会拒绝构建。声音登记由游戏读取，运行时仍没有新增 DLL、轮询、进程或网络消息。

本次角色声库、音频媒体、动画包与上次输出的摘要保持一致。补齐目录也覆盖学者的后置播报，不另改其时机。

## 验证范围

新增回归覆盖了“Wwise 中已有 Event，但游戏目录未登记”的缺口。最终包校验将实际 TAE 声音编号依次对应到 EIB、SBI、角色声库 HIRC、新声音媒体和本地 WEM 副本；十个角色的 SBI Event 集合与声库 Event 集合一致。

真实原始目录、构建结果、独立审查与完整链路报告保存在 `local/trigger-fix/`。本次没有启动游戏；目录的实际加载、播放和联机验收仍需与静态校验分开记录。
